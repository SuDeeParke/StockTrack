# StockTrack — 个人量化交易指挥台

## 问题陈述

*如何为独立量化交易者打造一个统一的 Web 界面，基于 InStock 成熟的分析引擎，同时覆盖 A 股与美股，提供每日买卖信号，并逐步扩展至策略回测和自动化交易执行？*

---

## 推荐方向

**以 InStock Python 后端为基础，构建双市场信号看板，前端使用现代 React 技术栈。**

架构设计：Fork InStock，将其 Flask 层替换为 **FastAPI**（更好的异步支持、自动生成 OpenAPI 文档）。保留 InStock 现有的 TA-Lib 信号引擎、MySQL 数据库结构和 A 股数据抓取器。新增一条美股数据管道（**yfinance / Alpaca**），输出与 A 股完全相同的标准化信号格式。StockTrack（本仓库）的 React 前端统一消费这些 API。

- **第一阶段**：只读信号看板，每日开盘前可直接使用
- **第二阶段**：可视化回测界面
- **第三阶段**：通过 Futu OpenAPI 接入港股/A 股/美股执行自动交易

**值得在第一天就做对的架构决策**：采用市场无关的数据模型。每个股票标的都包含 `market: 'CN' | 'US'` 字段，使用统一 Ticker 格式（如 `AAPL.US`、`600519.SH`）。这个改动成本极低，却能避免日后痛苦的重构。

---

## 技术选型

| 层级 | 选型 | 理由 |
|---|---|---|
| 后端 | Python + FastAPI | 复用 InStock 全部逻辑，API 设计优于 Flask |
| 数据库 | MySQL（现有） | 零迁移成本 |
| A 股数据 | akshare / tushare（InStock 现有） | 已稳定运行 |
| 美股数据 | yfinance + Alpaca | 免费，yfinance 无需 API Key |
| K 线图表 | Apache ECharts | K 线支持最佳，国内量化社区标准 |
| 前端 | React 19 + TypeScript + Vite | 本仓库已有脚手架 |
| 状态管理 | TanStack Query | 服务端状态缓存、后台自动刷新 |
| 样式 | Tailwind CSS | 暗色交易界面最快路径 |

## 待验证的核心假设

- [ ] **InStock 的 Flask 路由可以无缝迁移至 FastAPI，无需重写业务逻辑** — 验证方式：测试能否在 FastAPI handler 中直接 import InStock 的 DB 模型和指标函数（1 天可验证）
- [ ] **yfinance 日线 OHLCV + 基础指标足以产生美股信号** — InStock 使用的 MACD、RSI、成交量等指标可直接映射；先用 10 只股票测试信号质量
- [ ] **A 股与美股交易时间差不会造成 UX 混乱** — 看板需要清晰展示每个市场的"开市/收市"状态，美股信号在北京时间夜间推送
- [ ] **Futu OpenAPI 在你的运行环境中可用** — 需要本地运行 Futu 客户端；在设计第三阶段之前先验证这一点

## MVP 范围（第一阶段，约 4 周）

**包含：**
- FastAPI 后端，封装 InStock 现有信号引擎
- A 股每日数据刷新（InStock 管道）+ 美股成交量前 100（yfinance）
- 信号看板：今日信号列表，支持按指标类型 / 置信度排序
- 个股详情页：K 线图（ECharts）、关键指标值、最近 5 条信号
- 市场切换：沪深 / 美股 / 全部
- 暗色模式 UI

**不包含（留待后续阶段）：**
- 回测界面（第二阶段）
- 交易执行（第三阶段）
- 自选股 / 持仓管理
- 实时 / 分钟级数据（MVP 只用日线）
- 移动端适配
- 用户认证（单用户，本机或私有 VPS 部署）

---

## 明确不做（及原因）

- **用 TypeScript 重写 InStock 指标逻辑** — InStock 的 32+ 个指标经过多年验证，重写只带来风险，没有收益
- **第一阶段实时 Tick 推送** — 日线信号足以验证核心交易循环；实时数据在价值被证明前只会增加基础设施复杂度
- **社交 / 分享功能** — 个人工具，不需要用户体系
- **期权 / 期货** — 不同的数据结构和领域知识，留作后续独立决策
- **加密货币** — InStock 不支持，数据源完全不同
- **原生移动 App** — 响应式 Web 对个人工具已经足够
